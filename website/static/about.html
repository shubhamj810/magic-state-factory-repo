Factories

A factory is a binary matrix. Each column is a \pi/4 parity rotation, which consumes one noisy T state. Each row is a wire. The first k rows are outputs. The other r rows are checks, which are measured and postselected. The gate the factory applies to its outputs is read off the overlaps between rows.

The numbers

n
Noisy T states consumed per run.
k
Output qubits.
d
Distance. Input errors of rate p leave an output error of order p^d.
N,\ r
Wires in total, and the r = N - k checks.
V_{\mathrm{ex}}
T states one run yields. T and CS count one, CCZ counts two. It is undefined when the gate's terms share an output.
\gamma
\log(n/k)/\log d. Overhead per output qubit.
\gamma_T
\log(n/T)/\log d, with T the T-count of the output gate.
\gamma_\rho
\log(n/V_{\mathrm{ex}})/\log d. Overhead per extractable T state. Rankings use this one.

Lower is better for all three exponents, and for a pure T^{\otimes k} gate they agree. They differ for CS and CCZ gates, where counting output qubits can flatter a factory.

Distances

The catalogue holds distance 2 and up. A distance-2 factory detects every single faulty T state and suppresses errors to order p^2.

Every distance is re-checked from the circuit. An exact distance is proved (no undetectable damaging fault is lighter) and witnessed (one of that weight is shown). Otherwise the catalogue gives a proved lower bound.

A few sources certify a larger distance than could be re-checked here. Tables show both. Rankings and exponents use the certified one and mark it †. Where a source certifies a lower bound and a damaging fault of that weight is shown here, the two together give the distance, and the tag shows it without the ≥.

Clifford corrections

The output gate names only the non-Clifford part of what the rotations deposit. With every rotation a T=\mathrm{diag}(1,e^{i\pi/4}), the rest is a diagonal Clifford: S, Z and CZ gates on the wires. The factory undoes it after the rotations and before it measures the checks. Then its action is exactly the gate shown, and an error-free run passes every check. Each factory page lists this correction, derived as Bravyi and Haah do for triorthogonal codes.

Running some rotations as T^3, T^5 or T^\dagger instead of T costs the same magic states and can remove the correction altogether. For a code this is a transversal T gate, as in Jain and Albert. The search page can show only the factories that need no S or CZ gate, or only those that do.

How each number is obtained

Every row is re-derived from its circuit by verify_catalog.py when it enters the catalogue, and the whole file can be re-checked the same way at any time.

One row per magic state

Two circuits with the same n, k and d share a row when a CNOT circuit and S, Z and CZ gates on the outputs turn one gate into the other. Such gates prepare the same magic state. For example, \mathrm{T}_0\cdot\mathrm{T}_1 and \mathrm{T}_0\cdot\mathrm{CS}_{01} are one class. Each factory page has a tool that checks this for any target gate and builds the circuit.

Citing

Each factory page names its original source, the paper that found it or the person who contributed it. All of them are listed under References. For the catalogue as a whole, cite

    and the repository, github.com/shubhamj810/magic-state-factory-repo. GitHub's "Cite this repository" button gives the same in several formats.

    Most distance-2 factories come from the borrowed-identity searches of S. Singh, C. Gidney and C. Jones. If you use them, cite their paper, arXiv:2606.28518, and their code and catalogue, github.com/shraggy/Magic_state_factory_search.

    The factories of distance 9 to 31 are codes of S. P. Jain and V. V. Albert. If you use them, cite their paper, arXiv:2408.12752.

    Data

    • factories.csv, one row per factory.
    • index.json, the same with the reference table.
    • master_catalog.json, the full database.

    The site is rebuilt from master_catalog.json on every change. index.json records the commit it was built from.

    Contributing

    The catalogue is a community effort. Send a factory in any format, such as a paper, matrices, code or a notebook. Open a pull request with a folder in community_contributions/submissions, or attach it to an issue. Each submission is verified like any other row and credited to you on every class it adds.
